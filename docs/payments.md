# Заказы и mock-оплата

Это учебная оплата: деньги с карты не списываются.

| Шаг | Запрос |
| --- | --- |
| Бронь | `POST /reservations` с `event_id`, `seat_ids` |
| Заказ | `POST /orders` с `reservation_id` |
| Состав заказа | `GET /orders/{id}/items` |
| Оплата | `POST /payments/mock` с `order_id`, `idempotency_key` (UUID) |
| История | `GET /orders/me`, `GET /orders/{id}` |

Все запросы требуют Bearer-токен владельца. Сумму, валюту, цены и владельца
определяет сервер. Клиент не может передать свою сумму. Цены и названия тарифов
сохраняются в позициях заказа; деньги — Decimal, KZT.

Одна группа брони создаёт один заказ. Повтор `POST /orders` возвращает его с `200`
(первый запрос — `201`). Создание заказа не продлевает десятиминутную бронь.

Для оплаты сгенерируй UUID один раз и повторяй его при сетевых сбоях.
В одной транзакции создаётся Payment, заказ становится PAID, бронь COMPLETED,
и каждая позиция получает Ticket с уникальным QR UUID. Ответ содержит оплату и билеты.
Тот же ключ и заказ возвращают сохранённую оплату; другой заказ с этим ключом — `409`.
Повтор уже оплаченного заказа с новым ключом также даёт `409`.
Ключ уникален в пределах пользователя; второй успешной оплаты заказа быть не может.

Истёкшая бронь, закрытое или начавшееся событие не оплачиваются. Истечение переводит
связанный PENDING-заказ в CANCELLED. Платёж и выпуск билетов откатываются вместе
при конфликте: оплаченного заказа без билетов не остаётся.

Миграция `0003` добавляет `payments` и составной уникальный ключ владельца заказа.
Поле `refunded_at` фиксирует полный [mock-возврат](cancellations.md).
