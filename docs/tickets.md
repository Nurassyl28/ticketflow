# QR-билеты

| Маршрут | Доступ |
| --- | --- |
| `GET /tickets/me` | Свои билеты, `limit` 1–100 и `offset` |
| `GET /tickets/{id}` | Только владелец заказа |
| `GET /tickets/{id}/qr` | Только владелец VALID-билета; файл SVG |
| `POST /tickets/validate` | ORGANIZER своего события либо ADMIN |

JSON проверки: `{"event_id":"UUID события","qr_code":"UUID из QR"}`.
В QR записывается только случайный UUID билета. SVG генерируется локально
через [Segno](https://segno.readthedocs.io/en/latest/serializers.html), без внешних сервисов.
Ответы с билетами и изображением имеют `Cache-Control: no-store`.

Проверка требует PUBLISHED-событие, PAID-заказ и VALID-билет именно этого события.
Ограничения по времени входа пока нет: организатор может проверить билет до начала
и после начала, пока событие не переведено в FINISHED. Успех переводит билет в USED
и записывает аудит одной транзакцией. Повтор: `403 Ticket already used`.
Отменённое/закрытое событие и недействительный билет дают `403`; неизвестный токен,
другое событие и чужой организатор — `404`.

Общая блокировка события согласует сканирование с отменой; блокировка билета
позволяет только одно успешное сканирование. Даже ADMIN не скачивает чужой QR
через маршруты получения: эти маршруты всегда ограничены владельцем.
