# Аналитика и аудит

`GET /organizer/dashboard`: ORGANIZER видит свои события, ADMIN — все.
Параметр `event_id` ограничивает расчёт одним доступным событием; чужое — `404`.
Все шесть метрик вычисляются одним SQL-запросом в общем снимке данных.

| Метрика | Формула |
| --- | --- |
| `tickets_sold` | VALID/USED билеты с PAID-заказом и SUCCEEDED-платежом |
| `tickets_available` | Места будущих PUBLISHED-событий минус продажи и неистёкшие ACTIVE-брони |
| `total_revenue` | Сумма снимков цен оставшихся проданных билетов, KZT |
| `sales_today` | Количество этих билетов с датой оплаты сегодня по UTC |
| `sales_by_ticket_type` | ID/название тарифа, количество и выручка |
| `sales_by_date` | UTC-дата оплаты, количество и выручка |

Возврат исключает продажу из её исходной даты. Это нетто сохранённых продаж,
а не отчёт движения денег по дню возврата. USED продолжает считаться продажей.
Суммы сериализуются десятичными строками, включая вложенные группы; float не используется.
Пустые группы возвращаются как `[]`, показатели — как нули.

`GET /organizer/events/{id}/sales` показывает историю билетов, включая отменённые:
ID билета/заказа/места, тариф, цена, статусы и время оплаты. QR-токены и email
покупателя в этот список не входят. Доступ — владелец события либо ADMIN.

`GET /admin/audit-logs` доступен только ADMIN. Фильтры: `action`, `entity`, `entity_id`,
`user_id`, `date_from`, `date_to`. Пагинация списков: `limit` 1–100, `offset` от 0.
Аудит хранит роль-действие, сущность, ID, пользователя, время и IP; пароли и токены
не записываются. Изменение и запись аудита фиксируются в одной транзакции.
