# Правила работы с TicketFlow

- Общайся с пользователем по-русски, максимально кратко и понятно.
- Для планов, статусов и сравнений предпочитай небольшие Markdown-таблицы.
- Python, зависимости и инструменты запускай через `uv`: `uv sync`, `uv add`, `uv run`.
- Требования проекта находятся в `docs/spec.md`, план — в `docs/plan.md`.
- Не меняй исходное ТЗ молча: предлагаемые уточнения записывай в план.

## GitHub

- Каждый законченный, осмысленный блок изменений оформляй через issue,
  отдельную ветку, commit и PR; после успешных проверок сливай PR в `main`.
- Пользователь разрешил этот цикл для своих задач: отдельное подтверждение
  для обычного создания issue, commit, push, PR и merge не требуется.
  Обязательные ограничения среды и защиты веток сохраняются.
- Создавай issue перед работой, когда возможно; связывай PR через `Closes #N`.
- Добавляй в commit только относящиеся к задаче файлы; сохраняй чужие изменения.
- Перед merge проверь diff и подходящие проверки; дождись обязательного CI.
  Не обходи защиту веток и не сливай PR с упавшими проверками.
- После merge обнови локальную `main`, проверь закрытие issue и дай ссылки на issue/PR.
- Если GitHub недоступен, сообщи об этом; не называй commit, PR или merge завершёнными без проверки.
- Делай содержательные коммиты, без пустых изменений ради количества активности.
